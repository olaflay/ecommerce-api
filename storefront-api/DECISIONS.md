# DECISIONS.md — Architecture & Technical Decision Log

Every non-trivial design decision, edge case resolution, or deviation from default convention is logged here per PRD §26.12 and AGENTS.md Constitution Rule 8.

| # | Date | Context / Decision | Alternatives Considered | Rationale |
|---|---|---|---|---|
| 1 | 2026-09-15 | Money representation: integers in minor units (kobo, NGN). | Float, Decimal/Numeric. | PRD §4 & §6: Avoid rounding and precision loss in currency calculations; integer kobo is exact and standard. |
| 2 | 2026-09-15 | Identifiers: UUID v4 everywhere (`db.Uuid`). | Auto-increment serial integers. | PRD §4 & §21: Prevents enumeration attacks and matches multi-tenant/public API standards. |
| 3 | 2026-09-15 | Local PostgreSQL port set to `5434` in `.env` (Docker container `ecommerce-pg`). | Standard `5432`. | Avoids port conflicts with pre-existing local Postgres services on port 5432. |
| 4 | 2026-09-15 | Destructive truncate-and-regenerate seed strategy. | Non-destructive `upsert`. | PRD §15: Faker has no stable natural keys. Clean wipe guarantees deterministic row counts and zero drift across seed runs. |
| 5 | 2026-09-15 | Case-insensitive email uniqueness via lowercasing on write. | Citext extension or raw Postgres lower() index. | Consistent cross-platform behavior; ensures `ADA.OKAFOR@EXAMPLE.COM` matches `ada.okafor@example.com` cleanly across all environments. |
| 6 | 2026-09-16 | Mutation requests on read-only endpoints (e.g., `POST /api/v1/products`) return `404 Not Found` with standard error envelope. | `405 Method Not Allowed`. | Express routing does not mount unhandled methods on those paths, matching standard REST router behavior while returning a consistent error envelope. |
| 7 | 2026-09-16 | Exclude `/healthz` from rate limiting. | Rate limit `/healthz` with high threshold. | PRD §13 & §20: Hosting uptime monitors (Render/Railway) must never exhaust quota or cause false-positive downtime alerts. |
| 8 | 2026-09-16 | Duplicate product IDs in a single order creation request are merged by summing quantities. | Reject with `400`/`422`, or create duplicate line items. | PRD §6: Clean UX and database constraint hygiene; merges items before checking stock and snapshotting prices. |
| 9 | 2026-09-16 | Config validation with Zod fails fast on boot. | Runtime lazy evaluation. | PRD §20: Fails immediately at startup if any required environment variable is missing, avoiding runtime crashes. |
| 10 | 2026-09-16 | Row-level locking during order creation via `SELECT ... FOR UPDATE WHERE id = ANY(${productIds}::uuid[])` inside interactive transaction. | Application-level mutex or optimistic concurrency. | PRD §6: Database-level row locking prevents race conditions across distributed server instances and ensures strict stock integrity. |
| 11 | 2026-09-16 | Strict state machine transition validation (`pending -> paid|cancelled`, `paid -> shipped|cancelled`, `shipped -> delivered`). Idempotent same-status PATCH returns 200. | Free status updates or throwing 400. | PRD §6: Complies with e-commerce fulfillment lifecycle and avoids invalid business state transitions while providing idempotent API ergonomics. |
| 12 | 2026-09-16 | `DELETE /orders/:id` is restricted to pending orders and restocks line item quantities back into product stock before cascading deletion. | Allow deleting any order without restocking. | PRD §6: Inventory was decremented at order creation; hard-deleting a pending order must release stock back to the catalog. |
| 13 | 2026-09-16 | Storage-level PostgreSQL `CHECK` constraints (`check_product_stock_non_negative`, `check_product_price_positive`, etc.) added via migration. | Rely solely on application-level validation. | PRD §14: Provides true defense-in-depth preventing invalid state even if application logic were ever bypassed. |
| 14 | 2026-09-16 | Request correlation tracing via `X-Request-Id` UUID v4 header mounted as the first Express middleware. | No request tracing or console-only logs. | Enables tracing client requests through edge, proxy, server logs, and error middleware without leaking sensitive internal details. |
| 15 | 2026-09-16 | Consumer UI Zero Dead-End Resilience Architecture (M3 tonal error/empty cards, filter reset chips, server health check, offline listeners). | Basic text states with no recovery actions. | Eliminates UX dead ends for end users and evaluators; provides immediate 1-click recovery actions, active filter dismissal, and graceful cold-start feedback. |
| 16 | 2026-09-16 | Removed dead `scripts/dns-patcher.js` Node DNS monkey-patch. | Wire it in as the first import and keep. | Zero import sites, and broken under `"type":"module"` (uses `require`, would crash if loaded). More fundamentally it cannot work as intended: Prisma's Rust query engine performs its own DNS resolution and never consults Node's patched `dns.lookup`. Cold-start DNS resilience is covered by `sslmode=require` + `connection_limit` in `DATABASE_URL` per PRD §20, not Node-level patches. |
| 17 | 2026-09-16 | Order status transitions and pending-order deletion re-locked inside a `$transaction` via `SELECT ... FOR UPDATE` on the order row. | Nested conditional `updateMany({ where: { id, status } })` with count check. | Fixes the read-then-write TOCTOU race: a concurrent PATCH could apply a transition from an outdated status and resurrect a terminal (cancelled) order. The row lock serializes concurrent PATCH/delete against each other, matching the create-order locking pattern (decision 10), so every applied transition is validated against the current state under the lock (PRD §6). |
| 18 | 2026-09-16 | `PATCH /orders/:id` and `DELETE /orders/:id` now raise a `409` when a transaction re-reads a moved status, instead of silently applying the stale write. | Optimistic concurrency via `If-Match`/version column. | Row locking is consistent with the existing create-order approach and yields deterministic, conflict-explicit behavior without adding a client contract change. |
